## V1（收尾）：标定与最小闭环

**目标**：让现有骨架真机跑通"主界面→开卡→选3张→等动画→下一回合→胜利"。

**交付**
- 用 MFW 截的 720p 图标定：5 面卡 ROI/HSV、上排 NP 卡、场景（主界面/选卡/胜利/失败）、攻击钮坐标、选卡像素差阈值 `_DIFF_THRESHOLD`。
- 在 resource 建对应识别节点。
- 顺带补 **#1 主动选敌人目标**（多敌波次必需；需敌人坐标，跟标定一起做）。

**依赖**：真实 720p 截图（含普通选卡、选中态各一张；有 NP 卡的一张）。

**验收**：受控模拟器上连续通过若干不需技能的本；确认失败/未知场景能安全停止。

## V2：按固定攻略打周回本

**主题**：从"只会平A+宝具"升级到"能按攻略放技能三宝具清场"。这是让工具真正有用的关键跳跃（现在周回基本都要先叠 buff）。

### A. 主动技能（从者技能 + 御主技能）—— V2 核心
- 感知：技能可用/CD、**技能目标选择子屏**、御主技能。
- 执行：`cast_servant_skill(slot, idx, target_ally)`、`cast_master_skill(...)`，处理目标子屏后置确认。
- 契约：启用 `BattleAction.servant_skills / master_skills`（已预留字段）。

### B. 固定回合计划 TurnPlan（FGA 式）
- 每面预设"放哪些技能给谁、宝具顺序、是否换人"；选卡仍动态。
- **关键**：用固定计划则**无需理解技能效果**——策略由计划编码，程序只按计划点。伤害模拟/效果理解留到 V3。
- 契约新增 `TurnPlan / BattlePlan`；决策器按 TurnPlan 出技能序列 + 动态选卡。

### C. 按角色（卡归属识别）
- `owner_slot` 识别（模板或轻量 NN 分类）。
- 解锁：Brave chain、指定从者优先、计划按角色引用。

### D. 选目标 / 宝具顺序 / 换人
- 主动选目标（若 V1 未完成则并入）。
- 宝具顺序优化（先辅助后输出）。
- 换人 order change（三换队常用）。

**V2 内部建议顺序**：A+B（能按攻略打本）→ D（多敌与三换）→ C（Brave/按角色优化）。

**依赖**：从者/技能元数据（目标类型等，判断是否弹目标子屏）；真实截图标定技能/目标 UI。

## V2 补充项：Chaldea 配队接入

**目标**：把队伍名单、乃至每回合操作攻略从 Chaldea 导入，省掉手写 TurnPlan。

- 复用现有 `agent/chaldea/`（现用于配 BBC）。新增一个"转成 TeamSnapshot / TurnPlan"的转换器，与 `chaldea_converter.py`（转 BBC）并列。
- **两层数据**：
  - 名单（谁/站位/礼装/魔术礼装/等级）→ `TeamSnapshot` → 支撑 owner_slot、Brave、按角色。
  - 操作序列（若数据含）→ 直接转 `TurnPlan` → 免手写攻略。
- **铁律**：Chaldea 是先验计划，运行时仍以画面为准（实际抽卡/NP/存活由感知定）。
- **License**：仅用数据（项目已在用），不混入 AGPL 代码。
- **待查**：现有 chaldea 模块究竟解析了"操作序列"还是仅"名单"，决定能白嫖多少。

## 集成 / 鲁棒性轨（与 V2 并行）

让它能无人值守连刷，多为"需截图才能做"：
- **结算流程（#7）**：打完通关/掉落/点击继续到回主界面；原生路径尚未开发，需截图；可查 BBC 路径 `战斗完成信息` 能否复用。
- **进场动画 >15s（#4）**：首个未知等待超时可能误判卡死，需放宽/区分。
- **开场攻略提示、关卡机制提示弹窗（#5/#6）**：需"点一下继续"，当前会被当异常。
- **宝具封印可用态识别**：封印时 NP 卡出现但点不动；当前靠"变化确认"安全中止（打不过不乱来），要打过封印本需感知区分可用/封印态（需封印截图）。
- pipeline 集成：把 `auto_battle` 接入可调度入口（独立按钮 → custom action → 未来 pipeline 节点）。

## V3+：LLM 与模拟（远期）

规则 + 固定计划的 V2 稳定、且卡归属/结构化事实齐备后，才引入：
- `LLMDecider`：在本地生成的合法候选中做高层取舍 / 解释 / 离线复盘；接口与 `RuleDecider` 相同，替换即可。
- 伤害/NP 估值模拟：为决策提供清场概率等估值。
- 这才是"大模型接管"的合适时机——那时模型有可靠事实可推理，而非盲看截图。
