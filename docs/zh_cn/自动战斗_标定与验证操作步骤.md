# 自动战斗：标定与验证操作步骤

> 补齐截图后，按本文从"标定 ROI/坐标"到"验证识别准确率"一步步做。
> 工具在 `tools/battle_calib/`。前提：截图必须走 **MFW 截图链路、1280×720**，否则标的数不代表真机。

---

## 0. 依赖

```
pip install opencv-python numpy   # requirements.txt 已含
```

---

## 1. 截图（走 MFW 链路，1280×720）

各存一张到 `tests/fixtures/battle/screenshots/`（有 NP 卡的选卡界面尤其要）：

| 文件（建议名） | 场景 |
|---|---|
| main_001.png | 主界面（有攻击钮） |
| cmd_001.png | 选卡界面（普通） |
| cmd_selected_001.png | 选卡界面（点选后，含"行动N"徽标） |
| cmd_np_001.png | 选卡界面（有宝具卡上排） |
| victory_001.png / defeat_001.png | 胜利 / 失败 |
| （可选）dialog_001.png / seal_001.png | 弹窗 / 宝具封印 |

> 用 MFW 截图：Pipeline 里加一个 `"action":"Screencap"` 节点（存到 `log_dir/screencap/`），或用 MaaFramework 调试截图。**别用手机相册/其它分辨率的图。**

---

## 2. 标定 ROI 与坐标

编辑 `tools/battle_calib/calib_rois.json`，填 5 张面卡的 `card_roi`（`[x,y,w,h]`，框在**卡边框**那圈，避开左上角暴击星）、`np_roi`、`attack_btn`、`enemy_point`。

跑标定脚本看效果：

```bash
python tools/battle_calib/calibrate.py tests/fixtures/battle/screenshots/cmd_001.png
```

- 输出每张卡的 **预测卡色 / 置信度 / meanHSV / 各色像素数**；
- 生成 `cmd_001_overlay.png`：框和预测标签画在图上，肉眼核对框有没有对准、颜色判得对不对；
- 取坐标可加 `--pick`（弹窗点鼠标打印坐标，需图形界面）。

反复调 `card_roi`，必要时调 `tools/battle_calib/cv_perception.py` 里的 `HSV_BOUNDS`，直到 **5 张卡全判对**。

> **卡色 = 力击(B/红) / 技击(A/蓝) / 迅击(Q/绿)**。OpenCV HSV：H 0-179，红跨 0/179 两端（已用两段）。

---

## 3. 把标定结果落到运行时

标好的数字要填到两处（**保持一致**）：

1. **执行坐标** → `agent/battle/execution/coords.py`：`CARD_ROI` / `NP_ROI` / `ATTACK_BTN` / `ENEMY_POINT`。
2. **感知识别节点** → 在 `assets/resource/.../pipeline` 里建 MFW 节点，ROI 与 `HSV_BOUNDS` 对应：
   - `战斗_卡{1..5}_{B|A|Q}`：`ColorMatch`（`method:40` HSV，`lower/upper` 用标定的边界，`roi` 用 card_roi）；
   - `战斗_主界面` / `战斗_选卡场景` / `战斗_胜利` / `战斗_失败`：`TemplateMatch`（裁模板图）；
   - `战斗_NP卡{1..3}`：`TemplateMatch`（宝具卡框，**只匹配高亮可用态**，封印灰态自然不命中）；
   - `战斗_敌人{1..3}` / `_选中`。
3. 执行确认阈值 `_DIFF_THRESHOLD` → `agent/battle/execution/executor.py`（选卡前后像素差；先按 overlay 里选中态和未选态的差异估个值）。

> ColorMatch 的 `lower/upper` 必须与 `cv_perception.HSV_BOUNDS` 一致，离线验证才代表真机。

---

## 4. 感知离线验证（路 A，无需设备）

给每张选卡截图写一份同名标注 `xxx.json`（Tier-0）：

```json
{
  "screenshot": "cmd_001.png",
  "meta": {"server": "CN", "resolution": "1280x720", "team": [1,2,3]},
  "scene": "command_selection",
  "cards": [
    {"ui_slot": 1, "color": "Q"},
    {"ui_slot": 2, "color": "B"},
    {"ui_slot": 3, "color": "A"},
    {"ui_slot": 4, "color": "A"},
    {"ui_slot": 5, "color": "B"}
  ],
  "np_cards": [1, 3],
  "enemies": [{"slot": 1, "alive": true, "targeted": true}]
}
```

跑验证（用标定好的 `calib_rois.json`）：

```bash
python tools/battle_calib/verify_perception.py tests/fixtures/battle/screenshots/
```

- 逐张对比**卡色**预测与标注，报每张失配 + 总准确率（门槛 ≥99%）；
- `scene / np_cards / enemies` 当前跳过（需模板/真机），留待路 B 或真机。

不达标就回第 2 步继续调 ROI/HSV，直到卡色 ≥99%。

---

## 5. 感知真机验证（路 B，更忠实）

用 MFW 对静态图跑**真识别**（不需真机截图，但要有 Tasker+Resource）：

- `Tasker.post_recognition(reco_type, reco_param, image)` —— 对给定图片跑指定识别类型/参数，返回结果。
- 做法：加载我们的 resource → 建 Tasker（controller 可用占位/DbgController）→ 把截图传进去按节点参数跑 → 比对结果。
- 或直接在真机/模拟器上跑一场并开 **MFW debug 模式**（输出识别命中框图），肉眼确认识别对不对、以及"识别错还是决策错"。

---

## 6. 执行层 & 回合循环验证

- **无设备**：先做回合循环"可测性改造"，用 Fake 感知/执行跑组件测试（开卡、选3张顺序、确认失败停、动画等待、胜利/超时）。
- **真机**：受控模拟器跑一场，观察 主界面→开卡→选3张→自动发动→动画→下一回合 是否顺畅；确认点击命中、后置确认有效。

---

## 7. 验收门槛（架构文档同）

| 指标 | 门槛 |
|---|---|
| 选卡场景 / 卡色 / NP 卡识别 | ≥ 99% |
| 原子动作后置确认成功率 | ≥ 99.5% |
| 非法 Action 通过 Validator | 0 |
| 高风险动作误触发 | 0 |
| 低置信度仍执行 | 0 |

## 工具速查

| 文件 | 作用 |

| `tools/battle_calib/calib_rois.json` | ROI/坐标配置（你编辑） |
